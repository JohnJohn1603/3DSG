# Changes made for this handoff

The navigation, perception and graph algorithms are copied from the current working trees, including uncommitted navigation fixes. Original checkouts were not edited. Source ownership remains visible under `projects/`.

The supported workflow is `demo.py`, not the historical project launchers. It resolves all project/model/scene/native paths from its own location, writes bootstrap manifests and run outputs to an external output directory, and launches isolated Python environments selected through runtime JSON. `projects/3DSG/exploration/handoff_paths.py` is the new path contract. Entry-point defaults in `run_frontier_habitat.py`, `native_graph_plugin.py`, `replay_saved_native_keyframe.py` and `desktop.py` use it.

The old C2 result folder was used only to obtain three configuration flags. It is replaced by a new live configuration manifest containing the pipeline config and worker paths. It contains no frames, detections, features, graph state or previous room/object outputs. OpenCLIP's configuration file contains only the required feature contract, without historical preflight/run results.

The selected HM3D 00802 dataset descriptor preserves the original flat shader/up/front geometry settings and points only to the included basis mesh. Semantic GT meshes/labels and other scene directories are omitted. The spawn, calibrated floor, depth cameras and footprint contract are preserved. Copied 00802 JSON input files use relative asset paths for direct execution from `projects/3DSG`; spawn-only provenance replaces old route-bearing effective configuration inputs. `demo.py` materializes absolute input paths outside the source folder at runtime.

Native workers were rebuilt through a small CMake overlay using the bundled original target sources, OctoMap/CGAL prefixes, DuDe and MapConversion. It verifies vendored MapConversion file hashes against the pinned revision and sets `$ORIGIN/../lib`. Compiler intermediates are outside the source folder. Fresh environments use their installed PyTorch3D package and rebuilt extension. A runtime JSON can explicitly set `pytorch3d_source` to `third_party/pytorch3d-v0.7.4` when using the sender's old editable environment; this override is restricted to a path inside the bundle and prevents reads from its original editable checkout. The setup tool creates a non-editable installation on a fresh machine.

One relative internal symlink shares the upstream OccuSG reference between Fusion and Rebuild. Its resolved target stays inside this handoff; all other dependencies are copied files. Runtime Python environments and system graphics/native libraries remain external installation dependencies. The exported specs describe those dependencies without shipping the multi-gigabyte virtualenvs.

Legacy research scripts/configs/docs retain historical provenance and references to their old experiments; these paths are not used by the supported demo. Historical fixture/result folders are deliberately absent. Two already-applied cross-repository maintenance patchers from 3DSG are omitted from the handoff to prevent accidentally patching a different checkout. Their resulting current source changes are present in the copied mapper/runtime code.

The first file-access tracing attempt used strace, which was unavailable under the local ptrace restrictions. Verification instead used Python import/open audit hooks with explicit rejection of reads from the original project roots, plus native `ldd`/RUNPATH checks. This does not claim an operating-system-level trace of every third-party native syscall.
