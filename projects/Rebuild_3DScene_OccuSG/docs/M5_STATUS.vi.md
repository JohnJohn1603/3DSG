## Implementation

- `contracts/regions.py` defines `Polygon2D` with holes, raw
  `RegionObservation` (frame-local ID, timestamp, grid revision, centroid,
  area, optional source convex hull, raw adjacency and metadata),
  `CanonicalRegion`, retained `TrackedRegion`, `GuardDecision` and
  `RegionUpdateResult`.
- Timestamp and full last-seen polygon fields satisfy the standalone public
  contract; source matching/expiry use accepted-update frame index and retain
  only features, not full geometry history. Stored times/geometries do not
  affect matching. Raw IDs accept `str | int` at this boundary; source ROS IDs
  are integers.
- `regions/tracker.py` ports source feature extraction and greedy matcher:
  message area when positive, otherwise exterior-ring shoelace area; source
  convex-hull bounds when supplied (else polygon bounds); **bounding-box IoU**;
  inclusive area ratio and `(IoU >= min_iou OR distance <= max_distance)` gate;
  source score; lexicographic tie-break `(score desc, IoU desc, distance asc,
  canonical ID asc, current input index asc)`; greedy one-to-one assignment;
  monotonic IDs; miss count and expiry only at `miss_count > 3`. Adjacency raw
  IDs are remapped to current persistent IDs, sorted and deduplicated on
  `CanonicalRegion` in the current snapshot only. `TrackedRegion` deliberately
  has no adjacency field, so empty/stale edges cannot be mistaken for current.
  Current observations and retained track memory are separate outputs.
- `regions/guard.py` ports guard area/count/unknown/minimum logic. Guard area is
  the sum of positive reported region areas, **not** free-space cell area; the
  tracker’s area fallback is separate. Initial update checks minimum region
  count only. Later updates check zero/min count, unknown ratio, total reported
  area drop, and region count drop using strict `<` comparisons.
- `regions/pipeline.py` follows source order: guard first, tracker only after an
  accepted update. Reject returns prior canonical regions as stale only when
  configured and leaves tracker update index, miss counts, IDs and last-seen
  unchanged. This is Python guard/tracker state only; it does **not** transact
  or roll back internal DuDe/Incremental_Decomposer state.
- `config/schema.py` adds strict typed `regions.tracker` and `regions.guard`
  sections. Unknown keys, wrong scalar types and non-finite thresholds reject.
  `configs/reference_code.yaml`, `reference_code_mp3d.yaml` and
  `test_fixture.yaml` include the source-code runtime values. The `.85` drop
  parameters mean a minimum retained ratio of `1 - .85 = .15` (up to 85%
  reduction), not a 15% maximum reduction. This intentionally follows code/YAML,
  not the paper’s 15% statement.

## Expected outputs and test provenance

`tests/test_m5_regions.py` uses only hand-authored deterministic rectangles,
holes and split/merge-shaped synthetic geometries (`metadata.fixture=synthetic`).
Expected IDs/scores/guards are derived from the equations and comparator order
above, with arithmetic documented next to the relevant tests; no output was
generated by DuDe or by a golden-generation run of the new tracker.

Coverage includes raw ID/order changes; growth; bbox-IoU, distance and area
gates including inclusive bounds; score ordering and exact tie-break; greedy
conflicts; miss 1/2/3, expiry on miss 4 and reappearance before/after expiry;
current snapshot versus retained tracks; adjacency remapping, including two
adjacent regions and absence of adjacency on retained tracks; split/merge-shaped
observations without added lineage policy; first/empty/high-unknown updates;
unknown `.98` boundary; area/count drop boundaries and either side; reject then
valid; and no tracker age/last-seen refresh from a rejected update.

One numeric detail is intentionally preserved from C++ double arithmetic:
`1.0 - 0.85` evaluates to approximately `0.15000000000000002`, while integer
`3 / 20` is approximately `0.15`; that count case is therefore just below the
computed threshold under the source strict comparator. The regression records
the actual source expression rather than silently rounding it to a decimal
idealization.

## Limitations and differences

- Paper tracker differs: this is reference/code bbox-IoU + OR gate and greedy
  matching, not polygon-IoU + AND gates or Hungarian.
- For malformed/out-of-range config values, source `normalizeConfig()` silently
  clamps values; the standalone central schema rejects invalid values under
  the M0 strict-config contract. Valid active YAML parameters match source.
- Paper guard’s 15% rule differs from source/YAML `.85` max-drop parameters;
  implementation follows source-code expression and reports the difference.
- Source tracker itself can age tracks when called with an empty snapshot, but
  active guard call order rejects zero regions after a valid update before
  `canonicalize` is called. Direct tracker empty-snapshot tests isolate the
  tracker kernel; `RegionUpdateProcessor` never sends a rejected update into it.
- Split/merge tests document the baseline greedy ID outcomes only. No lineage,
  confirmation, multi-view evidence, or physical-room inference was added.
- Most tracker/guard tests remain synthetic; the M4 integration fixture does not establish whole-pipeline equivalence,
  whole-pipeline equivalence, or Kaggle evidence. No M6–M13 work was performed.
